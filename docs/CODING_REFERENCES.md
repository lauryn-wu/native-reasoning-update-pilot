# Coding reference construction

The references solve existing released variants; they do not replace or rewrite any initial statement, starter code, correction, or benchmark problem. Selection follows the existing hard-first, edit-size-first review inventory. No paid model outcome was observed. The independently reviewed prefix, reasons for exclusions, exact source joins, references, test hashes and validation evidence are recorded in `provenance/coding_review.json`.

## Published tests and safe acquisition

LiveCodeBench revision `0fe84c3912ea0c4d4a78037083943e8f0c4dd505`, `release_v6`, provides the public and hidden tests. The pinned `test5.jsonl` and `test6.jsonl` files have SHA-256 values equal to their Hugging Face LFS object identifiers; byte lengths and immutable URLs are in `provenance/upstream_tests_lock.json`. These two shards match 339 of the 341 update-release coding rows by the exact triple `(platform, contest_id, question_title)`. The unmatched rows 0 and 1 are outside the reviewed prefix. No unchecked row-index join is used.

For constructed cases, matching also checks the released source-original statement against the official full statement and the released original starter. Upstream `question_id`, file/line identity and hashes are retained. Most acquired suites contain 42–44 cases; task 250 contains six. Every public and private input is preserved, with no failure-based filtering. Large suites are batched for resource limits, not sampled. One demonstrably incorrect upstream answer for task 258 is preserved in the adjudication record and corrected in the separately hashed grading asset, as explained below.

Compressed private tests are decoded only in a pinned Docker image, without network or credentials, as UID/GID 65534, with read-only root, dropped capabilities, bounded CPU/memory/PIDs and runtime. The decoder rejects pickle globals and persistent references, bounds decompression, and accepts only the published pickled JSON-string format. The host never imports or executes source pickle content. Benchmark test payloads remain in the ignored user cache; the repository stores hashes, metadata and our reference source code.

## Reference arguments

**258 — starting-player correction.** The official [game proof](https://atcoder.jp/contests/arc192/editorial/12199?lang=en) combines the remaining capacity of already touched entries into a pass count, then reduces that count to its parity. Its nine cases yield: one entry is a first-player win; two entries a second-player win; three entries a first-player win unless all entries are even; for at least four entries, the first player wins exactly when the number of odd entries is odd. The initial task starts Snuke; the correction starts Fennec. Both references therefore use the same winner-role rule and exchange the player names. Literal minimax over unvisited capacities and pass counts independently checks 209 cases. Case-insensitive output is expressly allowed by the source and retained by the grader.

**167 — functional-graph monotone assignments.** Direct every vertex to its specified parent. Every directed cycle must have a common assigned value, by cycling the inequalities. For a tree vertex with fixed value v, each child's assignments contribute its cumulative count through v; multiply those independent child contributions. Remove leaves to aggregate into cycles, multiply the remaining vertex factors at each common cycle value, sum over that value, and multiply disconnected components. This is O(NM), with no assumption about an acyclic input. The two primes change only the final arithmetic ring. Independent exhaustive assignments check 864 small cases, and exact closed forms check full-size self-loop, chain and cycle families. The [published editorial](https://atcoder.jp/contests/abc387/editorial/11869?lang=en) supplies the same functional-graph decomposition.

**218 — reversing all edges.** State is `(vertex, orientation)`. Moving uses an edge in the current orientation and the variant's stated move cost, while paying X switches orientation at the same vertex. Nonnegative edge costs permit Dijkstra over this doubled graph. Independent Bellman–Ford on all transitions checks small directed graphs and flip costs; all published inputs are retained. No future constraints are appended to the initial prompt.

**268 — parenthesis-operation orbits.** Add a virtual outer pair and regard matching pairs as an ordered rooted tree. Every legal operation preserves the underlying unordered tree. Reversing two adjacent sibling subtrees and undoing each subtree's reflection exchanges them, so arbitrary sibling permutations are attainable. Canonical subtree identifiers are exact sorted child-identifier tuples. At each vertex multiply the child orbit counts and the multinomial count of distinct child-type orders. This is a constructive invariant and reachability argument; the [official proof](https://atcoder.jp/contests/arc194/editorial/12410?lang=ja) uses the same correspondence. An independent checker explores every directly allowed substring operation for all valid strings of length at most ten. Forests of distinct nested chains give 13!, 14!, 20! and 40! modular witnesses.

**269 — sum of distances over recursive trees.** Let T_i be the sum of expected distances over unordered pairs among the first i vertices. The expected sum of distances from new vertex i to preceding vertices is `R_i=(i−1)A_i+2T_(i−1)/(i−1)`, so update `T_i=T_(i−1)+R_i`. For fixed u and v>u, averaging over v's uniformly chosen parent gives `E[d(u,v)]=A_v+R_u/u+sum_(u<j<v) A_j/j`. Prefix sums answer each query; multiply by `(N−1)!` to recover the sum over all parent sequences. All denominators are nonzero modulo either prime on the published domain. Literal enumeration of every parent sequence through seven vertices and direct tree-distance traversal independently checks the formula, including large weights that distinguish moduli. The [official editorial](https://atcoder.jp/contests/arc195/editorial/12543?lang=en) provides a separate per-edge probability derivation.

**233 — shortest palindrome extension.** A shortest appended extension mirrors exactly the prefix outside the longest palindromic suffix. Compute that suffix using the prefix function of `reverse(S) + separator + S`. Reversing both input and result gives the initial prepend extension whose suffix is S. The separator is a non-character sentinel, avoiding any alphabet collision. Exhaustive literal enumeration of added binary strings checks both directions independently; official uppercase inputs retain their exact source format.

**250 — maximum cake-pair prices.** Assign each selected cake to the coordinate used by its pair, so each of the three coordinate groups has even cardinality. Start with the top 2K individual maxima; an optimum parity repair changes at most four items, and the best four candidates for each old-to-new category transition suffice. A constant-sized DP finds that repair. The full transfer-path argument and candidate replacement proof are in `references/coding/250/PROOF.md`, independently reviewed against literal matching and category-assignment enumeration. Adding one to every pair price adds exactly K to the optimum and preserves optimizers. All six published input files, including their many test cases, are retained.

**191 — kth three-array expression.** On nonnegative arrays, sort descending and traverse the monotone triple-index lattice with a unique-parent maximum heap. For the initial statement's general signed integers, a multilinear expression reaches a rectangular index box's maximum at a corner. Pop that corner, partition the box minus the corner into three disjoint slabs, and repeat. The heap therefore always exposes the largest unreported value without duplicates. The signed path does not assume the positivity constraints supplied only in the correction. Adding one preserves rank and shifts the answer by exactly one. `references/coding/191/PROOF.md` records this argument; separate literal order-statistic checks include signed arrays and independently enumerated edge cases.

**124 — degree-constrained maximum tree weight.** Root the tree. For each node compute the best descendant weight when its parent edge is absent and present. A child edge contributes its weight plus the child's parent-present optimum minus its parent-absent optimum. Add the largest positive gains up to the remaining degree budget. Induction over the rooted tree establishes optimality because child subtrees are disjoint. The source update changes the required method name; algorithmic behavior is otherwise unchanged. Both variants use the full official tests with their respective entrypoints. This is an interface-only correction and must be labeled as such in analysis.

**299 — V-shaped diagonal direction.** For each cell/direction, compute the maximum straight continuation with the required alternating values. A second DP allows either continuing in that direction with one turn still available, or taking the single permitted turn and using the straight table. The traversal order places successors first. Maximize over starting cells labeled 1. Horizontal reflection exchanges clockwise and counterclockwise turns while preserving values and length, so reflected official inputs with unchanged expected answers form exact initial tests.

**158 — unique middle mode.** Fix each middle index with value x. If the two selected left and two selected right positions contain at least two additional x values, x appears at least three times and is necessarily the unique mode. Count these choices by binomial products. If there is exactly one additional x, the other three values must be pairwise distinct. Count a singleton on one side and distinct pairs on the other, excluding that singleton's value; sum symmetrically. No other cases qualify. The exact integer sum is reduced modulo the variant's stated modulus. The initial modulo-1,000,000,009 expectations are generated only after the algorithm is checked against official modulo-1,000,000,007 answers and independent small exhaustive enumeration.

**337 — common prefixes after deletion.** A trie node qualifies precisely when its prefix count is at least k. Removing one word can invalidate only nodes on that word's path whose count was exactly k. Maintain counts of qualifying nodes at each depth, temporarily subtract those nodes, query the largest nonempty depth, and restore. Cases leaving fewer than k strings return the explicit variant sentinel. Initial expected answers equal official answers except that exact insufficient-count case changes 0 to −1.

**317 — divisions to zero.** For base b, a positive integer requires its base-b digit length in divisions to become zero. Sum these lengths over each integer interval using power boundaries. An operation performs two unit reductions on distinct elements. The minimum is `max(maximum individual depth, ceil(total depth/2))`; for the official domain `l < r`, two adjacent largest values ensure the individual-depth bound never exceeds the latter. Thus the result is the sum of interval ceilings. Base 5 is the initial task and base 4 the corrected task. Independent small state-space search checks the scheduling argument. Input-domain requirements remain explicit in qualification; this reference is not a claim about undefined one-element intervals.

**328 — minimum-cost caption and tie direction.** A suffix DP tracks the previous character and current run length capped at three. Continuing a run increments/caps its length; changing character is legal only after a run reaches three. The cost of changing an input character is alphabet distance. Terminal states accept only completed runs. Recover an optimal string greedily by trying next characters in ascending or descending order while preserving the DP optimum. This proves the lexicographic minimum/maximum tie rule. The released correction also restores the misspelled starter entrypoint. Independent exhaustive short-string enumeration checks both costs and tie resolution.

**151 — longest run objective.** For a maximum allowed all-one run L, each existing one-run of length r needs `floor(r/(L+1))` flips. Flipping ones to zeros cannot join one-runs, so the bound is attainable independently per run. Binary-search L, including zero. For the corrected identical-character objective and L ≥ 2, the same formula applies to every run and internal flip positions avoid harmful joining. L = 1 is the separate alternating-string case. Independent enumeration of all flip subsets verifies both variants on small binary strings.

**331 — shortest wildcard substring and argument order.** Split the pattern on `*`, find all occurrences of each literal piece, then for each first-piece start greedily take the earliest nonoverlapping occurrence of every next piece. An earlier end never harms feasibility or length, proving greediness for that start. Minimize over starts. Empty pieces have occurrences at all boundaries. For initial tests, duplicate the first wildcard, obtaining exactly three stars without changing its language, and swap arguments as required by the exact initial starter. The source correction restores both the two-star contract and argument order. Additional independent tests use separated three-star pieces; no test treats a two-star pattern as valid initial input.

**154 — matching versus nonmatching adjacency.** Choose the positions where adjacent values change, choose the first value in m ways, and choose each changed value in m−1 ways. The count is `C(n−1,changes) * m * (m−1)^changes`. Initial changes equal k, corrected changes equal n−1−k. Map official corrected k to initial n−1−k and reorder arguments to match the initial signature; expected outputs are unchanged. Independent exhaustive arrays check the formula and parameter binding.

**325 — Manhattan sum over arrangements.** Each unordered pair of cells occurs in `C(mn−2,k−2)` arrangements. Sum row distances and column distances separately, yielding `[n²m(m²−1)+m²n(n²−1)]/6`. Multiply by that binomial factor. The initial ordered-distinct-pair requirement doubles the sum; corrected unordered pairs do not. Initial tests therefore double official answers modulo 1,000,000,007 and use the released initial method name. Both endpoint/pair conventions are checked by independent small-grid enumeration.

**117 — sum of good subsequences.** Maintain counts and sums of valid subsequences ending at each value. A new x starts a singleton and extends precisely subsequences ending at x−1 or x+1. Each extension adds x per sequence. Accumulate the new sums once, and reduce using the stated variant modulus. Independent subsequence enumeration checks the recurrence before generating initial-modulus expectations.

**162 — weighted nonoverlapping intervals.** Sort by right endpoint. The last compatible prefix ends strictly before the next interval's left endpoint because intervals are closed. DP over prefix and allowed number chosen compares skipping the current interval with taking it after the compatible prefix. Store maximum weight and the lexicographically smallest sorted original-index tuple on ties. Use at most five intervals initially and four after correction, with respective method names. Independent subset enumeration verifies endpoint overlap, capacity, weight and tie handling.

**148 — common character frequency.** Fix target frequency t; every alphabet position ends with count zero or t. Start from independent deletion/insertion costs. Transferring a surplus character to the adjacent deficient character saves one operation per transferred unit, capped by the two quantities. A position cannot simultaneously have surplus and deficit, so these savings do not compete. Transfers over two or more steps cannot beat deletion plus insertion. A two-choice alphabet DP subtracts these adjacent savings. It suffices to consider t from one through the largest input count; a higher target cannot improve costs. Reversing alphabet counts transforms previous-letter moves to next-letter moves. Independent small-state search verifies this reasoning and a direction-sensitive witness.

Passing an implementation against its own generated answers is not independent evidence. For newly derived initial outputs, qualification requires the written argument, agreement of the corrected reference with every official test, and a separate reviewer's exhaustive/brute-force checks using a different formulation. Algebraic transformations are additionally checked against direct reference execution. Cross-grading must show each stale reference fails the other variant, while both references pass their own complete suite.

These are finite test suites plus reviewed algorithms, not a claim that finite tests prove every arbitrary contestant program correct. Interface-only changes and semantic changes remain distinguishable metadata. Reference construction does not authorize paid execution; the explicit user hold and every other protocol/budget gate remain in force.
